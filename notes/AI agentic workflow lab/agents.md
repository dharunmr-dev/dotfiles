# Knowledge Base Article Review & Publishing Agent

## Project Overview

This project is an Agentic Workflow that automates the review and publishing of Knowledge Base (KB) articles.

Unlike a traditional article reviewer, this system does **not** assume a fixed documentation standard.

Instead, every organization uploads its own documentation standard (PDF/Markdown/Text), and the workflow dynamically interprets that standard before reviewing the submitted knowledge base article.

The goal is to simulate how enterprises review documentation before publishing it to an internal or public Knowledge Base.

The workflow demonstrates:

- Multi-Agent Architecture
    
- Task Decomposition
    
- Parallel Agent Execution
    
- Shared Policy Context
    
- LLM-based Decision Making
    
- Publishing Automation
    

---

# Primary User

Technical Writer

The technical writer uploads:

1. Organization Documentation Standard
    
2. Knowledge Base Article
    

The system returns:

- Review Report
    
- Publishing Decision
    

If approved, the article is stored in the published knowledge base.

# Shared State

Every agent must receive the same structured policy generated by the Standard Parser Agent.

Agents must never read the original PDF directly.

Only the Standard Parser Agent may interpret the uploaded documentation standard.

This keeps the architecture modular and prevents duplicated work.

# Standard Review Output Contract

All review agents (Compliance, Grammar, and Style Reviewer) MUST return a standardized response format.

This provides a common interface between agents, allowing the Decision Agent to aggregate results without custom parsing logic.

## Response Schema

```json
{
  "agent": "Grammar Agent",

  "overall_score": 91,

  "status": "PASS_WITH_WARNINGS",

  "summary": {},

  "findings": []
}
```

---

## Finding Schema

Every finding must follow this structure.

```json
{
  "id": "GRAM-001",

  "severity": "HIGH",

  "category": "Grammar",

  "location": {
    "page": 2,
    "section": "Steps",
    "step": 3,
    "paragraph": 1,
    "line": 2
  },

  "detected_text": "User click the Reset button.",

  "problem": "The verb does not agree with the singular subject.",

  "explanation": "The singular subject 'User' requires the verb 'clicks'.",

  "correction": {
    "type": "replacement",
    "original": "click",
    "replacement": "clicks"
  },

  "rule_reference": "Subject–Verb Agreement",

  "confidence": 0.99
}
```

---

## Severity Levels

| Level | Meaning |
|--------|---------|
| LOW | Minor issue that does not affect publishing |
| MEDIUM | Recommended improvement |
| HIGH | Significant quality issue requiring revision |
| CRITICAL | Publishing blocker |

---

## Location Object

Every finding should identify the exact location whenever possible.

```json
{
    "page": 2,
    "section": "Steps",
    "step": 3,
    "paragraph": 1,
    "line": 2
}
```

If a field is unavailable, return `null`.

---

## Correction Types

### Replacement

```json
{
    "type":"replacement",
    "original":"recieve",
    "replacement":"receive"
}
```

### Rewrite

```json
{
    "type":"rewrite",
    "replacement":"Click the Reset button after entering your password."
}
```

# Agent 1

## Name

Standard Parser Agent

## Purpose

Interpret the uploaded organization documentation standard and convert it into structured review rules.

This agent is responsible for understanding company policies.

It does NOT review articles.

---

### Input

Organization Standard

Supported formats

- PDF
    
- Markdown
    
- TXT
    

---

### Responsibilities

Extract:

- Mandatory sections
    
- Writing style
    
- Tone
    
- Voice
    
- Required metadata
    
- Formatting rules
    
- Article type
    
- Approval criteria
    

Ignore:

- Company history
    
- Contact details
    
- Non-review information
    

---

### Output

```json
{
  "article_type":"How-To",

  "mandatory_sections":[
      "Title",
      "Summary",
      "Prerequisites",
      "Steps",
      "Expected Result"
  ],

  "tone":"Professional",

  "voice":"Active",

  "required_metadata":[
      "Tags",
      "Category"
  ],

  "style_rules":[
      "Use second person",
      "Avoid slang",
      "Use numbered steps"
  ]
}
```

This JSON becomes the shared policy for every downstream agent.

# Agent 2

## Name

Compliance Agent

## Purpose

Validate whether the submitted article follows the organization policy.

---

### Input

Knowledge Base Article

Structured Policy

---

### Responsibilities

Check:

- Missing sections
    
- Missing metadata
    
- Required headings
    
- Required structure
    
- Rule violations
    

Do NOT check:

- Grammar
    
- Tone
    
- Writing quality
    

---

```json

  "status": "PASS_WITH_WARNINGS",

    "missing_metadata": 0,
    "policy_violations": 0

      "id": "COMP-001",

      "severity": "MEDIUM",

      "category": "Structure",

        "page": 3,
```

# Parallel Execution

The following agents must execute simultaneously.

- Compliance Agent
    
- Grammar Agent
    
- Style Reviewer Agent
    

Reason:

They do not depend on one another.

Each agent only requires

- Article
    
- Structured Policy (where applicable)
    

Parallel execution reduces latency and demonstrates proper agent orchestration.

# Agent 5

## Name

Decision Agent

## Purpose

Aggregate every review result and produce the final publishing decision.

This is an LLM-powered reasoning agent.

It must NOT simply average scores.

Instead, it should reason over every report.

---

### Input

Compliance Report

Grammar Report

Style Report

---

### Responsibilities

Generate

Overall Review Summary

Publishing Decision

Decision Reasoning

Improvement Suggestions

---

### Decisions

APPROVE

REVISION_REQUIRED

REJECT

---

### Output

```json
{
  "decision": "REVISION_REQUIRED",

  "overall_score": 89,

  "summary": "The article follows the required structure but contains several language and style issues that should be corrected before publication.",

  "reasoning": {
    "compliance": "PASS_WITH_WARNINGS",
    "grammar": "PASS_WITH_WARNINGS",
    "style": "PASS_WITH_WARNINGS"
  },

  "total_findings": {
    "critical": 0,
    "high": 1,
    "medium": 2,
    "low": 1
  },

  "recommendations": [
    "Correct subject–verb agreement.",
    "Add the Related Articles section.",
    "Use a professional tone in the Summary."
  ]
}
```

# Engineering Principles

Every agent has a single responsibility.

Agents communicate using structured JSON.

The Standard Parser Agent is the only component allowed to interpret organization standards.

Review agents execute in parallel.

Decision Agent performs reasoning rather than fixed rule evaluation.

Publishing Agent performs the only write operation.
